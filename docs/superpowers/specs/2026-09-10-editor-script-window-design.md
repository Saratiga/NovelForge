# NovelForge — Редакторские инструменты, часть 2: окно редактора скрипта — дизайн

## Цель и рамки

Вторая из трёх независимых частей фазы "Редакторские инструменты" (см. `docs/superpowers/specs/2026-09-10-editor-scripted-importer-design.md` — часть 1, `ScriptedImporter`, уже смержена). Даёт `.nfscript`-файлам собственное редакторское окно вместо открытия во внешнем текстовом редакторе: подсветка синтаксиса, панель ошибок парсинга (обновляется по мере набора), автодополнение команд/персонажей/меток по Tab.

**Вне рамок этой фазы**:
- Inline squiggly-подчёркивание ошибок прямо под строкой, как в IDE — по решению при брейнсторминге заменено на панель/список ошибок под редактором (строка + текст, клик → переход к строке). Экономит значительный объём UI-инженерии (пересчёт пиксельной геометрии позиции символа в IMGUI/UI Toolkit текст-контроле) без потери содержательной функции — автор всё равно узнаёт о каждой ошибке с номером строки сразу при вводе.
- Граф ветвлений (`GraphView`, round-trip сериализация) — третья часть декомпозиции, отдельная фаза.
- Построчные номера в желобе, multi-file вкладки (второй открытый файл — второе окно, не таб), find/replace, undo сверх того, что даёт сам IMGUI `TextArea` из коробки.
- Расширяемость автодополнения под кастомные источники (переменные, сцены и т.п.) — только команды, персонажи, метки, как в исходной мастер-спеке.

## Почему это, как и предыдущая часть, чисто аддитивно

Не трогает `NovelForge.Runtime`/`NovelForge.UI`, кроме одного точечного дополнения к уже смерженному `Runtime/Parsing/CommandRegistry.cs` (перечисление зарегистрированных имён команд — сейчас взять список неоткуда, нужен для автодополнения). Всё остальное — новые файлы в уже существующей `NovelForge.Editor`.

## Ключевое техническое решение: подсветка через IMGUI-оверлей

Готового Unity-виджета с посимвольной раскраской РЕДАКТИРУЕМОГО текста нет ни в IMGUI, ни в UI Toolkit — обе технологии требуют самодельной прослойки сравнимой сложности. Выбран IMGUI (устоявшийся в Unity-сообществе приём): два слоя в одном `Rect`, один `GUIStyle`/шрифт/размер у обоих —
- снизу `GUI.Label` с `richText=true`, отображающий текст с `<color=...>`-разметкой (только для чтения);
- сверху `EditorGUI.TextArea` с прозрачным цветом текста (виден только курсор/выделение), обрабатывающий реальный ввод как обычный plain-text (без тегов в редактируемой строке).

IMGUI, а не UI Toolkit — весь существующий Editor-код проекта (`ScriptedImporter`) уже в этом стиле; UI Toolkit стал бы первой новой технологией в проекте без выигрыша в сложности для этой конкретной задачи (игровой UI принципиально только UGUI, по мастер-спеке).

## Разделение на тестируемую логику и GUI-обвязку

IMGUI-окна (`OnGUI`) практически не тестируются в EditMode — нет устоявшегося способа прогнать repaint-цикл. Поэтому вся содержательная логика — в чистых классах без зависимости от `EditorWindow`:

- **`Editor/DslSyntaxHighlighter.cs`** — `public static string ToRichText(string source)`.
- **`Editor/DslAutocompleteProvider.cs`** — `public static IReadOnlyList<string> GetCandidates(string source, int cursorPosition, IEnumerable<string> commands, IEnumerable<string> characters)`.
- **`Editor/NovelScriptEditorWindow.cs`** — тонкая обвязка: раскладка `OnGUI`, обработка клавиш, вызовы `ScriptCompiler.Compile`/двух классов выше, сохранение. Не тестируется автоматически.

## Точечное дополнение к `CommandRegistry`

`Runtime/Parsing/CommandRegistry.cs` получает:
```csharp
public IReadOnlyCollection<string> RegisteredNames => _factories.Keys;
```
Единственный источник списка команд для автодополнения — сейчас перечислить зарегистрированные команды неоткуда.

## `DslSyntaxHighlighter`

Построчная, безопасная на некорректном вводе классификация через regex (никогда не бросает — на нераспознанной строке текст остаётся некрашеным):

- `// комментарий` — целиком приглушённым цветом.
- Ключевые слова `label`, `jump`, `gosub`, `return`, `choice`, `if`/`else`/`endif`, `set` — цвет ключевого слова.
- Реплика (`Character: текст ...`) — id персонажа своим цветом; `#emotion`, `@id` теги и `left`/`right`/`center` в конце — каждый своим.
- Вариант выбора (`"текст" [@id] -> label`) — самодостаточно узнаваем по структуре (кавычки + `->`), не требует знания, что мы внутри `choice`-блока; кавычки один цвет, целевая метка — цвет метки.
- Общая команда (`bg`/`cg`/`music`/`sfx`/`wait`/нераспознанное слово в начале строки) — цвет команды.

Цвета — пара (dark/light) через `EditorGUIUtility.isProSkin`, простые константы.

## Панель ошибок

Дебаунс не нужен — компиляция скрипта миллисекундная (см. часть 1): `ScriptCompiler.Compile(text)` в try/catch вызывается синхронно на каждое изменение текста. `ScriptCompiler` останавливается на первой ошибке, поэтому панель показывает не список, а одну текущую: `ParseException.LineNumber` + `.Message` в плашке под `TextArea`, либо ничего при валидном скрипте. Клик по плашке переносит курсор `TextArea` на указанную строку.

## Автодополнение

По Tab (перехватывается в `OnGUI` через `Event.current`, `Event.current.Use()` до того, как дойдёт до `TextArea`):

1. `DslAutocompleteProvider` берёт частичное слово перед курсором. Три источника:
   - Команды — `CommandRegistry.CreateDefault().RegisteredNames`.
   - Персонажи — `AssetDatabase.FindAssets("t:CharacterDefinition")`, `CharacterDefinition.Id` каждого.
   - Метки — построчный regex-скан ТЕКУЩЕГО текста на `^\s*label\s+(\S+)`, не через `ScriptCompiler.Compile` — работает, даже если где-то дальше в скрипте синтаксическая ошибка (типичная ситуация во время набора).
2. Фильтр без сложного fuzzy-алгоритма: сперва кандидаты, начинающиеся с введённого (case-insensitive), затем остальные с введённым как подстрокой; внутри группы — алфавитный порядок.
3. Показ — `UnityEditor.GenericMenu`, не самописный dropdown: нативная клавиатурная навигация/мышь/Esc, `DropDown(rect)` у курсора — бесплатно. Список кандидатов фиксируется в момент Tab, не перефильтровывается при дальнейшем наборе внутри меню — упрощение, полностью рабочее автодополнение. Выбор заменяет частичное слово под курсором на кандидата.

## Открытие, сохранение, жизненный цикл

- **Открытие** — `[OnOpenAsset]`-хук (`UnityEditor.Callbacks`) перехватывает двойной клик по `NovelScriptAsset`; если окно для этого пути уже открыто — фокусирует его вместо второго экземпляра.
- **Источник истины** — сам `.nfscript`-файл на диске, не `NovelScriptAsset.Source` (тот лишь кэш последнего импорта). Открытие читает файл напрямую.
- **Сохранение** — явно по Ctrl+S, и автоматически при потере фокуса окна (`OnLostFocus`) и при закрытии (`OnDestroy`), без диалогов подтверждения: `File.WriteAllText` по пути ассета, затем `AssetDatabase.ImportAsset(path, ImportAssetOptions.ForceUpdate)`, чтобы реально сработал `NovelScriptImporter` и `NovelScriptAsset.Source` обновился.
- Заголовок окна получает `*` при несохранённых изменениях.

## Тестирование

EditMode-тесты только там, где реально тестируется:

- **`DslSyntaxHighlighter`** — по тесту на тип строки (label, реплика с `#emotion`+`@id`+position, вариант выбора, комментарий, известная/неизвестная generic-команда) — проверяем нужные `<color>`-обёртки.
- **`DslAutocompleteProvider`** — извлечение частичного слова в разных позициях курсора; сортировка (startswith → contains → алфавит); сбор меток из текста с ошибкой в другом месте; объединение всех трёх источников.
- **`CommandRegistry.RegisteredNames`** — совпадает с 5 встроенными командами `CreateDefault()`.
- `NovelScriptEditorWindow`, хук `[OnOpenAsset]`, `GenericMenu`-попап, реальное сохранение+реимпорт — не автоматизируются, тот же принцип, что уже применялся к визуальным вещам в проекте. Проверяются вручную по сценарию: открыть окно на тестовом `.nfscript`, набрать текст с ошибкой и без, увидеть подсветку и панель ошибок, вызвать автодополнение по Tab на каждом из трёх источников, сохранить по Ctrl+S и подтвердить, что `NovelScriptAsset.Source` реимпортировался.

# NovelForge — дизайн UPM-пакета для визуальных новелл в Unity

## Цель и рамки

Личный переиспользуемый инструмент для создания визуальных новелл в Unity, распространяемый
как UPM-пакет (локальный/git), чтобы подключать его в разные игры без копипасты.
Целевые платформы: PC (Windows/Mac/Linux) и мобильные (Android/iOS).

Не цель: продукт для широкой аудитории, документация уровня Asset Store, поддержка
произвольных сторонних UI-систем "из коробки" (UI Toolkit и т.п.) — только UGUI.

## MVP — обязательные возможности

- Диалоги, ветвления, выбор игрока
- Save/Load, переменные и флаги
- Спрайты персонажей с эмоциями и позами
- Локализация (мультиязычность текста и озвучки)
- Полный аудио-стек: музыка, SFX, озвучка реплик
- Фоны и CG-иллюстрации
- Редактор DSL-сценариев с подсветкой синтаксиса и автодополнением
- Read/write-визуализация графа ветвлений
- Руководство пользователя (README/USAGE) с примерами

## Архитектурное решение: модель рантайма

Рассматривались три варианта исполнения сценария:

1. **Плоский список команд + простая VM** (как Ren'Py/Naninovel/Fungus) — парсер превращает
   DSL в линейный список команд с метками; рантайм — указатель, идущий по списку, с
   переходами (jump/gosub/return) для ветвлений.
2. **Полноценный AST + tree-walking интерпретатор** (как Ink) — мощнее для сложной
   процедурной логики (функции, циклы), но на порядок сложнее в реализации с нуля.
3. Вариант 1, расширенный подпрограммами (gosub/return) для переиспользования кусков
   диалога без copy-paste.

**Выбран вариант 3** — даёт весь нужный функционал (ветвления, переиспользуемые куски,
условия) при существенно меньшей сложности и рисках, чем построение AST-интерпретатора
уровня Ink. Оправдано только личным масштабом использования: сложная процедурная генерация
текста не требуется.

## Модульная структура пакета

Три asmdef без лишнего дробления:

- **`NovelForge.Runtime`** — парсер DSL, VM/плеер, система команд, Actors (персонажи), Audio,
  Backgrounds, Save/Load, локализация, переменные. Вся логика, без UI-верстки.
- **`NovelForge.UI`** — дефолтная реализация экрана диалога/выбора/save-load на UGUI.
  Зависит от Runtime только через события/интерфейсы — заменяема без изменений в Runtime.
- **`NovelForge.Editor`** — редакторские инструменты: редактор сценариев, визуализация графа,
  кастомный `ScriptedImporter`. Editor-only, не попадает в билд.

## Поток данных

1. Автор пишет файл сценария (`.nfscript`, обычный текст) — либо руками, либо через
   встроенный редактор/граф (см. ниже).
2. Кастомный `ScriptedImporter` парсит его при импорте в Unity → ассет `NovelScript` с
   готовым списком команд (IR: `List<Command>` + `Dictionary<string,int> labels`).
   Синтаксическая ошибка = ошибка импорта с номером строки в консоли.
3. `PlaybackController` хранит указатель (`int pointer`) и стек вызовов
   (`Stack<int> callStack`). Цикл: взять `commands[pointer]`, вызвать
   `IEnumerator Execute(StoryContext ctx)`, дождаться завершения; если команда сама не
   поменяла `pointer` (это делают jump/gosub/return/choice) — `pointer++`.
4. Команды дёргают подсистемы (Actors/Audio/Backgrounds/Variables) через общий
   `StoryContext`, ничего не зная друг о друге напрямую.
5. UI подписан на события плеера (`OnLineShown`, `OnChoicesReady`, `OnSaveRequested`, ...) —
   не знает про VM напрямую.

## Синтаксис DSL

```
label start
  bg park_day
  music theme_calm

  Alice: Привет! #happy left
  Alice: Как дела?

  choice
    "Хорошо, спасибо!" -> good_response
    "Не очень..." -> bad_response

label good_response
  Alice: Приятно слышать!
  jump chapter2

label bad_response
  set relationship -= 1
  Alice: Что случилось?
  jump chapter2

label common_reaction
  Alice: (кивает) #neutral
  return
```

- `label` — метка сцены.
- `ИмяПерсонажа: текст` — реплика; `#emotion` и `left/right/center` — необязательные
  модификаторы позы/эмоции.
- `choice` + список вариантов со стрелкой на метку.
- `jump` / `gosub` / `return` — переходы и переиспользуемые подпрограммы.
- `set` — работа с переменными.
- Остальные строки (`bg`, `music`, `sfx`, `wait`, ...) — вызовы встроенных команд по общему
  синтаксису "имя_команды аргументы"; новая команда регистрируется как класс `Command` с
  именем, парсер не нужно трогать.
- `if/else` разворачивается на этапе компиляции в условный jump — отдельной ветки исполнения
  для условий не требуется.

## Контент-подсистемы

- **Actors** — `CharacterDefinition` (ScriptableObject): id, имя, цвет реплик, словарь
  "эмоция+поза → Sprite". `ActorView` — рантайм-компонент, показывающий нужный спрайт с
  простым fade/slide переходом (пресеты, не полноценная анимационная система — для
  кастомной анимации персонажа всегда можно дёрнуть его Animator напрямую).
- **Audio** — `AudioManager` с каналом музыки (кроссфейд при смене трека) и каналом SFX
  (несколько одновременных одноразовых звуков). Озвучка реплики — `AudioClip`, привязанный к
  id реплики, проигрывается синхронно с показом текста и обрывается при пропуске.
- **Backgrounds/CG** — тот же принцип, что Actors: `bg <id>` меняет фон сцены с fade,
  `cg <id>` показывает полноэкранную иллюстрацию поверх для ключевых моментов.

## Save/Load и переменные

- **VariableStore** — `Dictionary<string, object>` (int/float/bool/string), мутируется
  командой `set`.
- **SaveData** — снимок: id скрипта + позиция указателя + стек вызовов + дамп
  VariableStore + версия схемы. Расширяется через `ISaveParticipant` для
  игро-специфичного состояния.
- **ISaveStorage** — дефолтная реализация JSON-в-файл (`Application.persistentDataPath`,
  кроссплатформенно, включая мобильные). Несовместимая версия сейва → типизированное
  событие ("save incompatible"), не exception наружу.

## Локализация

Каждая реплика получает стабильный id (авто-хэш `label + порядковый номер`, либо явный id в
DSL). `LocalizationTable` (ScriptableObject/CSV на локаль): `id → перевод` (+ опционально путь
к озвучке на этом языке). `LocaleManager.Current` — активная локаль; PlaybackController перед
показом реплики запрашивает перевод по id, при отсутствии — фоллбэк на исходный текст из
DSL с предупреждением в лог, без краша.

## Инструменты редактора

### Редактор сценариев

Кастомное `EditorWindow`, открывается двойным кликом по `.nfscript`:

- Подсветка синтаксиса (метки, команды, персонажи, реплики, комментарии).
- Ошибки парсинга подчёркиваются под строкой в реальном времени (тот же парсер, что у
  `ScriptedImporter`, гоняется с debounce при вводе).
- Автодополнение по Ctrl+Space/Tab: команды (встроенные + зарегистрированные кастомные),
  персонажи (сканирует `CharacterDefinition` в проекте), существующие метки (для
  jump/gosub) — обычный fuzzy-match список.

### Граф ветвлений (read/write)

- Текст `.nfscript` остаётся единственным файлом на диске и в git — источник правды.
- Окно графа (`EditorWindow` на Unity `GraphView`) парсит текст в модель `GraphDocument`
  (узлы = метки/реплики/choice, рёбра = jump/gosub/переходы choice).
- Редактирование в графе: правка текста реплики прямо в узле, перетаскивание связи
  choice-варианта на другую метку, добавление/удаление узла, пересоздание jump. Правки
  меняют только модель `GraphDocument`, не файл напрямую.
- **Save** (кнопка + авто при потере фокуса окна) сериализует `GraphDocument` обратно в
  текст каноничным форматтером. Комментарии при парсинге прикрепляются к ближайшей
  следующей команде как метаданные и пишутся обратно рядом с ней — переживают round-trip.
  Порядок и форматирование нетронутых графом команд сохраняется как было.
- Конфликт (файл изменился на диске снаружи, пока в графе есть несохранённые правки) не
  сливается автоматически — явный диалог "перезагрузить с диска" / "оставить правки графа
  и перезаписать".
- Позиции узлов на холсте (визуальные, не влияют на исполнение) хранятся отдельно, в
  side-car файле `<script>.nfgraph.meta` рядом со скриптом — раскладка не теряется между
  открытиями и не засоряет сам DSL-текст.
- Граф read-only при просмотре недостижимого/битого места (например метка не найдена) —
  показывает проблемный узел визуально, не падает.

## UI-слой (UGUI)

Дефолтные префабы в `NovelForge.UI`:

- `DialogueBoxView` — имя, текст (эффект печати по буквам), аватар.
- `ChoiceView` — список кнопок под текущие варианты.
- `SaveLoadView` — сетка слотов.

Каждый подписывается на события `PlaybackController` и ничего не знает о VM напрямую —
собственная верстка под конкретную игру просто не использует эти префабы и подписывается на
те же события.

## Обработка ошибок

- Ошибка парсинга DSL → падает импорт ассета, с файлом/строкой в консоли Unity — нельзя
  случайно затащить в билд битый скрипт.
- Рантайм-ошибка (нет спрайта на эмоцию, нет ключа локализации, нет аудиоклипа) →
  `Debug.LogError` с контекстом, воспроизведение не останавливается, используется
  заглушка/фоллбэк.
- Несовместимый сейв → типизированное событие, не exception наружу.
- Конфликт графа/текста → явный диалог выбора, без автослияния.

## Тестирование

EditMode-тесты (Unity Test Runner, без сцены) на:

- Парсер: текст → ожидаемый список команд.
- VM: пошаговая работа указателя, gosub/return, jump, условия, переменные.
- Сериализатор графа: round-trip текст → `GraphDocument` → текст сохраняет семантику и
  комментарии.

Визуальные вещи (спрайты, аудио, UI, сам граф-редактор) проверяются вручную через демо-сцену
в `Samples~` — автоматизация пиксельных/визуальных проверок избыточна для личного проекта.

## Deliverable: руководство пользователя

По завершении реализации — `README.md`/`USAGE.md` в корне пакета с описанием синтаксиса
DSL, установки пакета через UPM, структуры проекта (где лежат персонажи/локализация/сейвы),
и пошаговым примером создания простой сцены с нуля.
